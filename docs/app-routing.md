# Адрес VPN и маршрутизация приложений

У адреса VPN-узла и адреса выхода в интернет разные роли. Для VDSina они могут совпадать, поэтому чужое приложение, чей трафик идёт через VPN, может узнать этот адрес, запросив у внешнего сервиса «какой у меня IP». Это не означает, что приложение прочитало закрытую конфигурацию Ноны.

| Маршрут приложения на Android | IP, который видит его удалённый сервис | Что остаётся возможным |
|---|---|---|
| Через VPN | Выходной IP выбранного узла | Приложение может проверить этот IP и определить признак VPN |
| Исключено из VPN | Публичный IP обычной Wi-Fi/мобильной сети | Приложение всё ещё может узнать о факте VPN через разрешённые системные признаки; абсолютной скрытности нет |
| Нет соединения с VPN | IP обычной сети | Приложение может хранить сведения, полученные раньше |

Закрытие окна Ноны не останавливает VPN-службу автоматически. И открытие или закрытие **чужого** приложения не является надёжной границей доступа к IP: оно может работать в фоне, а его сервер видит IP каждого запроса. Поэтому политика задаётся **для приложения целиком**, а не только на время, когда виден его экран.

В Android `VpnService.Builder.addDisallowedApplication()` выводит указанный установленный пакет из VPN. Список задаётся перед `establish()`; изменение списка требует пересоздать туннель. В разделе «Интернет без VPN» пользователь выбирает автоматическое правило для приложений, меняет маршрут каждого приложения и добавляет свои сайты. `NonaVpnService` читает сохранённую локальную политику независимо от окна Flutter. Существующие ручные исключения переносятся в новую политику при первом сохранении. На тестовом телефоне MAX (`ru.oneme.app`) ранее исключался из VPN; правило действует и для фоновой работы приложения.

Для полного локального списка пользовательских приложений, в том числе без иконки запуска, Android-сборка запрашивает `QUERY_ALL_PACKAGES`. Список не отправляется на сервер. Системные службы без пользовательского интерфейса скрыты из экрана. Публикация в Google Play потребует отдельной декларации этого разрешения и оценки его допустимости. После установки или удаления приложения и после изменения списка работающий туннель нужно переподключить: Android не позволяет менять список исключённых приложений у уже созданного интерфейса.

Режим «Все российские приложения» использует префикс `ru.` и небольшой проверяемый каталог известных пакетов, включая `com.vkontakte.android` и `com.idamob.tinkoff.android`; режим «Только банки и сервисы» использует только отмеченные в каталоге пакеты. Это эвристика: пакет `com.` не означает иностранное приложение, а `ru.` не доказывает российское происхождение. Нет достоверного полного списка приложений, которые определяют VPN; поведение каждого приложения может измениться. Пользователь может вручную исправить любой выбор. Если включён системный Android lockdown («блокировать соединения без VPN»), прямой маршрут может быть недоступен. Идентификаторы банков и сервисов сверены по страницам [Сбера](https://www.rustore.ru/catalog/app/ru.sberbankmobile), [ВТБ](https://www.rustore.ru/catalog/app/ru.vtb24.mobilebanking.android), [Альфа-Банка](https://www.rustore.ru/catalog/app/ru.alfabank.mobile.android), [Т-Банка](https://www.rustore.ru/catalog/app/com.idamob.tinkoff.android), [Госуслуг](https://www.rustore.ru/catalog/app/ru.rostel), [MAX](https://play.google.com/store/apps/details?id=ru.oneme.app) и [ВКонтакте](https://www.rustore.ru/catalog/app/com.vkontakte.android).

Для сайтов Xray получает упорядоченные правила: свои домены напрямую, исключения каталога через VPN, затем российские зоны и выбранные домены напрямую. Правила включают поддомены и применяются после переподключения. Домен определяется по доступному Xray имени HTTP/TLS/QUIC; шифрование имени сайта, собственный DNS приложения, IP-подключение или CDN могут помешать распознаванию. Поэтому кнопка «Все российские сайты» означает покрытие указанных зон и каталога, а не гарантию для любого российского сервиса. Для приложений, которым важно не использовать VPN ни для одного запроса, надёжнее исключить приложение целиком. Реальный выходной IP для новых правил сайтов пока не проверен живым подключением; режимы по умолчанию выключены.

На обычном iPhone произвольная per-app VPN-политика недоступна без MDM. Там остаются маршруты по IP/подсетям и ограничения, описанные в `architecture.md`.
