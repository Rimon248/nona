# Адрес VPN и маршрутизация приложений

У адреса VPN-узла и адреса выхода в интернет разные роли. Для VDSina они могут совпадать, поэтому чужое приложение, чей трафик идёт через VPN, может узнать этот адрес, запросив у внешнего сервиса «какой у меня IP». Это не означает, что приложение прочитало закрытую конфигурацию Ноны.

| Маршрут приложения на Android | IP, который видит его удалённый сервис | Что остаётся возможным |
|---|---|---|
| Через VPN | Выходной IP выбранного узла | Приложение может проверить этот IP и определить признак VPN |
| Исключено из VPN | Публичный IP обычной Wi-Fi/мобильной сети | Приложение всё ещё может узнать о факте VPN через разрешённые системные признаки; абсолютной скрытности нет |
| Нет соединения с VPN | IP обычной сети | Приложение может хранить сведения, полученные раньше |

Закрытие окна Ноны не останавливает VPN-службу автоматически. И открытие или закрытие **чужого** приложения не является надёжной границей доступа к IP: оно может работать в фоне, а его сервер видит IP каждого запроса. Поэтому политика задаётся **для приложения целиком**, а не только на время, когда виден его экран.

В Android `VpnService.Builder.addDisallowedApplication()` выводит указанный установленный пакет из VPN. Список задаётся перед `establish()`; изменение списка требует пересоздать туннель. В приложении теперь есть экран выбора приложений с иконкой запуска, валидируемая политика `AppRoutingPolicy` и нативное хранилище списка. Будущая VPN-служба сможет читать его через `AndroidAppExclusions.applySaved()` независимо от окна Flutter. Нативный метод намеренно бросает ошибку при несуществующем пакете — служба должна прервать подключение, а не молча проигнорировать исключение. **Сейчас сам VPN-туннель ещё не реализован, поэтому сохранённый список пока не применяется к трафику.**

Экран использует объявленный в manifest запрос `MAIN`/`LAUNCHER`, а не разрешение на просмотр всех установленных приложений. Поэтому приложения без иконки запуска могут отсутствовать в списке. После установки или удаления приложения и после изменения списка работающий туннель придётся пересоздать; это часть следующего этапа. Нельзя оставлять старую конфигурацию и утверждать, что новое исключение уже действует.

Не следует автоматически считать все приложения «российскими» по названию или стране разработчика. Выбор прямого маршрута должен быть явным, с понятной проверкой внешнего IP и повторной проверкой после обновления приложения. Если пользователь включил системный Android lockdown («блокировать соединения без VPN»), прямой маршрут может оказаться недоступным; Нона должна показать конфликт, а не обещать работу исключения.

На обычном iPhone произвольная per-app VPN-политика недоступна без MDM. Там остаются маршруты по IP/подсетям и ограничения, описанные в `architecture.md`.

Источники: [Android VPN guide](https://developer.android.com/develop/connectivity/vpn), [VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder), [Apple per-app VPN](https://developer.apple.com/documentation/networkextension/netunnelprovidermanager).
