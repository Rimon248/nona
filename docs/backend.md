# Сервер аккаунтов

Домашняя установка использует отдельный Keycloak Ноны и OIDC-режим API. Keycloak отвечает за пароль, вход и обновление токенов; PostgreSQL API хранит связь проверенного Keycloak `sub` с локальным аккаунтом, устройства и подписанные пакеты конфигурации. Публичная самостоятельная регистрация отключена. Вход в приложении происходит через системный браузер с PKCE. Токены хранятся средствами защищённого хранилища ОС; при выходе приложение отзывает refresh token.

В OIDC-режиме API принимает `Authorization: Bearer <access_token>`, проверяет RS256-подпись по JWKS отдельного Keycloak, точные issuer `https://nona.server.basketref.ru/auth/realms/nona`, audience `nona-api`, `azp=nona-client` и сроки действия. `GET /v1/account` создаёт локальную связь при первом обращении. Старые маршруты `/v1/sessions*` отключены. Локальный режим с собственными паролями сохранён в коде для разработки, но на домашнем сервере не используется.

Миграции применяются по порядку: `sql/001_accounts.sql`, `002_devices.sql`, `003_device_configurations.sql`, `004_oidc_accounts.sql`. На действующей БД перед переключением API на OIDC сделана резервная копия и применена четвёртая миграция. Не запускайте новый API против БД без неё.

API отдаёт только заранее установленный, подписанный и зашифрованный для устройства пакет. Автоматический выпуск и отзыв VPN credentials на VDSina ещё не реализованы. Ручная установка пакета через локальную команду `admin install-configuration ACCOUNT_ID DEVICE_ID ENVELOPE_FILE` предназначена для разработки и требует заранее доверенного публичного ключа проверки. Клиент пока не подключает полученный пакет к VPN-ядру.

Развёртывание и адрес — в [инструкции домашнего сервера](../deploy/home/README.md) и [плане публикации](publication.md).
