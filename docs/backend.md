# Сервер аккаунтов

Домашняя установка использует отдельный Keycloak Ноны и OIDC-режим API. Keycloak отвечает за пароль, вход и обновление токенов; PostgreSQL API хранит связь проверенного Keycloak `sub` с локальным аккаунтом, устройства и подписанные пакеты конфигурации. Публичная самостоятельная регистрация отключена. Вход в приложении происходит через системный браузер с PKCE. Токены хранятся средствами защищённого хранилища ОС; при выходе приложение отзывает refresh token.

В OIDC-режиме API принимает `Authorization: Bearer <access_token>`, проверяет RS256-подпись по JWKS отдельного Keycloak, точные issuer `https://nona.server.basketref.ru/auth/realms/nona`, audience `nona-api`, `azp=nona-client` и сроки действия. `GET /v1/account` создаёт локальную связь при первом обращении. Старые маршруты `/v1/sessions*` отключены. Локальный режим с собственными паролями сохранён в коде для разработки, но на домашнем сервере не используется.

Миграции применяются по порядку из каталога `sql`, включая `005_device_remote_credentials.sql`. На действующей БД перед переключением API на OIDC сделана резервная копия. Не запускайте новый API против БД без всех миграций.

API отдаёт только подписанный и зашифрованный для устройства пакет. На домашнем сервере операторская команда `admin provision-device ACCOUNT_ID DEVICE_ID` создаёт персональные credentials VDSina и пакет; `admin retire-device ACCOUNT_ID DEVICE_ID` отзывает их. Автоматический запуск этих команд после регистрации и при отзыве устройства ещё не подключён. Локальная команда `admin install-configuration ACCOUNT_ID DEVICE_ID ENVELOPE_FILE` остаётся для разработки.

`configbundle.BuildForDevice` шифрует данные узла для публичного ключа конкретного устройства и подписывает пакет. Адаптер `internal/node3xui` обращается к API клиентов 3x-ui по HTTPS с отдельным токеном, ограничивает операции идентификаторами `nona_` и не пересылает токен при перенаправлении. Живая операторская выдача на VDSina проверена для тестового устройства. Токен `nona-provisioner` хранится с правами `0600` только в `/srv/docker/nona/secrets/vdsina_3xui_token` на домашнем сервере; значение не включено в Git и сборки.

На действующем VDSina проверена версия 3x-ui `3.11.0`, а также наличие входов Hysteria2 и VLESS. API этой ветки управляет клиентами через `/panel/api/clients`, включая создание и удаление; точные схемы и поведение нужно сверить на конкретном узле перед первым изменением клиентов. [Официальная документация API клиентов](https://docs.sanaei.dev/docs/reference/api/clients/).

Развёртывание и адрес — в [инструкции домашнего сервера](../deploy/home/README.md) и [плане публикации](publication.md).
