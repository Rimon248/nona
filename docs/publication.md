# Публикация Ноны и отдельный Keycloak

Состояние на 10 ноября 2026 года. У Ноны есть собственные контейнеры Keycloak и PostgreSQL, собственная область `nona` и два OIDC-клиента: `nona-client` для приложения и `nona-panel` для операторской панели. Существующий Keycloak BasketStat не используется и не изменялся. Регистрация без приглашения выключена. Приложение использует один OIDC issuer `https://nona.server.basketref.ru/auth/realms/nona` и системный браузер с Authorization Code + PKCE, а API проверяет токен.

Keycloak и API установлены на домашнем сервере без опубликованных портов. Caddy локально пропускает `/auth/realms/nona*` и `/auth/resources/*` к Keycloak, `/v1/*` к API. Административные URL Keycloak, `master` realm и `/readyz` через этот домен закрыты. Сейчас Caddy использует `tls internal`, а публичная A-запись у Beget указывает на `192.168.3.24`. Вне домашней сети без WireGuard вход ещё не работает.

## Операторский аккаунт

Аккаунт `roman` создан в отдельной области Ноны с ролью `nona-operator`. Временный пароль хранится только на домашнем сервере в `/srv/docker/nona/secrets/roman_initial_password`; его следует получить по SSH и сразу сменить. Почта **не отмечена подтверждённой**: принадлежность адреса ещё не проверена. Для проверки нужен настроенный SMTP и письмо с одноразовой ссылкой Keycloak. Не устанавливайте `emailVerified=true` вручную. До подтверждения почты и проверки входа маршрут операторской панели не публикуется.

Защитный контейнер панели описан в `deploy/home/compose.auth.yaml`. Он пропускает только роль `nona-operator`. Его текущий upstream `static://200` лишь проверяет вход: функции управления пользователями, узлами и заданиями ещё не написаны. Мобильный API принимает Bearer access token от Keycloak и не использует браузерный cookie панели. Для приложения и панели нужны разные клиенты в одном отдельном Keycloak, чтобы отдельно ограничить redirect URI и доступ.

## Что осталось для внешнего доступа

1. Настроить SMTP для Keycloak Ноны, отправить письмо подтверждения `roman`, проверить адрес через ссылку из письма и сменить временный пароль.
2. Запустить `panel-auth` и проверить вход с ролью, отказ без роли и отсутствие доступа к панели без сессии.
3. Изменить **публичную** A-запись `nona.server.basketref.ru` с `192.168.3.24` на актуальный внешний IP домашнего подключения. Локальную запись MikroTik `192.168.3.24` оставить.
4. Заменить локальный блок Caddy на `deploy/home/Caddyfile.public.example` после проверки конфигурации и резервной копии. Получить обычный доверенный HTTPS-сертификат.
5. С телефона в мобильной сети без WireGuard проверить discovery OIDC, вход, `GET /v1/info`, закрытые `/auth/admin/`, `/auth/realms/master`, `/readyz`, а также сохранность других домашних сайтов.

Не приглашайте пользователей до автоматического выпуска и отзыва индивидуальных VLESS+REALITY/Hysteria2 credentials, резервного копирования обеих баз и проверки восстановления. Сейчас вход и учёт устройств работают; работающий VPN-доступ по аккаунту пока не выдаётся.
