# Публичный адрес Ноны и вход

Состояние на 10 ноября 2026 года. `nona.server.basketref.ru` опубликован через домашний Caddy с сертификатом Let's Encrypt. Публичная A-запись Beget указывает на `78.107.88.57`; локальная запись MikroTik остаётся `192.168.3.24`. Внешняя проверка `/v1/info` получила HTTP 200, а владелец открыл API и вошёл в панель через мобильный интернет без WireGuard. Локально сертификат проверен без исключений; `/auth/admin/`, `/auth/realms/master` и `/readyz` возвращают 404. Другие домашние сайты продолжают отвечать.

Отдельный Keycloak Ноны и отдельная его база работают без опубликованных портов хоста. Область `nona` содержит публичный клиент `nona-client` для приложения и закрытый `nona-panel` для панели. Публичны только пути входа области `nona` и необходимые ресурсы Keycloak. Самостоятельная регистрация отключена.

## Доступ

Почта **не подтверждается письмом** по решению владельца. Keycloak не требует `verifyEmail`; OAuth2 Proxy принимает неподтверждённый email, но допускает к панели только пользователя с ролью `nona-operator`. Это осознанное исключение из проверки email, а не отметка адреса как проверенного. Не используйте неподтверждённый email как доказательство личности и не выдавайте роль оператора на основании одного адреса. Для защиты остаются пароль, защита Keycloak от перебора, роль и отдельный OIDC-клиент. Восстановление пароля через email выключено; оператор с доступом к серверу сбрасывает пароль вручную.

Первый оператор `roman` создан с ролью `nona-operator`. Его временный пароль хранится только в `/srv/docker/nona/secrets/roman_initial_password` на домашнем сервере. Его нужно получить через SSH и сменить при первом входе; значение нельзя отправлять в чат или добавлять в Git.

`/` перенаправляет на `/admin/`. Без сессии панель направляет на Keycloak. Экран панели показывает текущий статус Keycloak, API и выдачи VPN-доступа; изменение пользователей, узлов и заданий пока не реализовано. `/v1/*` доступен через интернет: персональные маршруты требуют Bearer access token с подписью, точным issuer, audience `nona-api` и клиентом `nona-client`. `/v1/info` доступен без токена. Вход в приложение использует Authorization Code + PKCE через системный браузер.

## Проверено и что осталось

- Публичные DNS у Beget и 1.1.1.1 отвечают `78.107.88.57`; [внешняя проверка](https://check-host.net/check-report/56afa495kcba) получила `200` от `/v1/info` в Болгарии, Гонконге, Иране и Казахстане.
- [Проверка из двух сетей Москвы](https://check-host.net/check-report/56c6222fkce9) получила `200` для Ноны на `78.107.88.57`. [RefLab](https://check-host.net/check-report/56c622d7kc7e) также ответил `200` на том же IP. Оба домена сейчас обслуживает домашний Caddy; комментарий о старом хостинге в блоке RefLab его конфигурации устарел.
- Caddy получил сертификат Let's Encrypt через HTTP-01. Локальные запросы к новому HTTPS проходят проверку сертификата.
- [Внешняя проверка Keycloak](https://check-host.net/check-report/56afd62eka05) получила `200` в трёх сетях; [панель без сессии](https://check-host.net/check-report/56afd687k771) отвечает `302` в трёх сетях. Административные пути Keycloak и `/readyz` закрыты. Homarr продолжает отвечать `200`.
- Владелец подтвердил вход `roman` и экран «Обзор Ноны» сначала в домашней сети, затем через мобильный интернет без WireGuard. Причина первоначального сбоя на мобильном интернете не установлена; после изменения DNS он исчез без изменения маршрутизации или Caddy.
- Тестовая Android-сборка с публичным адресом API установлена на Samsung SM-S936B (Android API 37). После нажатия «Войти через Нону» приложение показало аккаунт `roman` и статус «Устройство зарегистрировано». После принудительного закрытия и повторного открытия вход и регистрация восстановились. Отдельно проверить вход с полностью очищенной сессией и через мобильный интернет ещё предстоит.
- Текущая тестовая Android-сборка содержит только публичный ключ проверки конфигураций, а персональные VPN-данные получает в зашифрованном подписанном пакете после входа. Пароли, токены и закрытые ключи в APK не включены.
- Операторский provisioner создал персональный доступ на VDSina и пакет версии 2 для тестового Android-устройства. Hysteria2 через Xray/libXray подтвердил выходной IP `195.63.146.49`; VLESS+REALITY с Android пока не подтверждён. Кнопка «Отключить» удаляет VPN-сеть Android. MAX исключён из неё по UID.
- Существующая панель VDSina проверена по SSH с ключом Mac: 3x-ui `3.11.0`, два входа VLESS и Hysteria2. Отдельный токен `nona-provisioner` хранится только на домашнем сервере с правами `0600`. Автоматическая выдача новым устройствам и узлы AdminVPS/Aeza ещё не подключены.
