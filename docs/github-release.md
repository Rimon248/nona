# Подготовка Android-релиза для GitHub

Сборка предназначена для прямого скачивания APK со страницы GitHub Releases. Android-клиент находится на ранней стадии; текущая версия приложения — `0.1.1`.

## Что делает релизный процесс

- Tag вида `v0.1.1` запускает GitHub Actions на Ubuntu и собирает APK для Android.
- APK подписывается постоянным ключом владельца, получает идентификатор `ru.basketref.nona` и пару SHA-256.
- Actions публикует APK на GitHub Releases только после отправки тега в GitHub.
- Debug-сборка использует прежний debug-ключ Android и не предназначена для распространения. Релизная сборка без личного release-keystore запрещена.

Workflow закрепляет `actions/checkout` полным SHA версии `v6.0.3`, а Flutter SDK — версией `3.47.9` (Dart 3.13.7, совместим с ограничением проекта). Требуется установленный на GitHub runner Android SDK и JDK 17 или совместимее.

## Однократная настройка владельцем

1. Создать постоянный Android upload keystore и надёжно сохранить резервную копию отдельно от GitHub и репозитория. Если потерять ключ, обновить установленное приложение тем же package ID будет нельзя.
2. Добавить в Settings → Secrets and variables → Actions четыре secrets: `NONA_ANDROID_KEYSTORE_BASE64`, `NONA_ANDROID_STORE_PASSWORD`, `NONA_ANDROID_KEY_ALIAS`, `NONA_ANDROID_KEY_PASSWORD`. Первый secret — base64 содержимого keystore. Не коммитить keystore, пароли или их копии.
3. Настроить GitHub remote для репозитория и проверить, что организация/аккаунт разрешает GitHub Actions создавать Releases.
4. Перед первым тегом выбрать и добавить лицензию для кода Ноны. Сейчас собственной лицензии в репозитории нет; лицензии Xray/libXray в `third_party` не дают разрешение на распространение остального кода.
5. Подготовить публичную политику конфиденциальности и контакт поддержки. Клиент обращается к `nona.server.basketref.ru`; регистрация доступна публично, а VPN-конфигурации выдает администратор после одобрения. Политика должна соответствовать фактическим срокам хранения аккаунтов, устройств и журналов на домашнем сервере.
6. Проверить нагрузку и доступность домашнего API для внешних пользователей и подтвердить, что администратор готов одобрять новые аккаунты. Публичность панели администратора при этом не требуется.
7. Обновить `version` в `apps/client/pubspec.yaml`, выполнить локальную проверку Android-сборки, создать tag той же версии, например `v0.1.1`, и отправить tag в GitHub. Это публикует доступный всем APK.

## Для пользователя Android

После публикации пользователь скачивает APK и checksum со страницы Releases проекта. Android может попросить разрешить установку приложения из браузера или файлового менеджера. Затем пользователь открывает Нону, регистрируется через «Войти через Нону» и ждёт решения администратора о VPN-доступе. Регистрация не означает, что VPN уже одобрен или доступен.

Установка релиза использует `ru.basketref.nona`. Она может существовать рядом с прежней тестовой debug-сборкой `com.example.nona_client`; Android не обновит debug-сборку автоматически. Это первый пакет для релизного канала, поэтому владельцу следует отдельно проверить вход, получение конфигурации, установку VPN и маршрутизацию на подписанной сборке до объявления релиза пользователям.

## Текущие ограничения

- Настроен только Android APK. iOS требует распространения через Apple; Windows и macOS здесь не публикуются.
- Наличие публичного API и формы регистрации не гарантирует постоянную доступность домашнего сервера или достаточную ёмкость VPN-узла.
- Доступность VPN-транспорта сейчас требует повторной проверки; инструкция не обещает работающий туннель.
- Раздел маршрутизации требует `QUERY_ALL_PACKAGES`, чтобы показать установленные приложения. Это подходит для прямого APK с GitHub; перед Google Play потребуется отдельная проверка требований магазина.
- Не создавайте тег, пока не выбраны лицензия кода и политика конфиденциальности, не сохранён ключ подписи и не проверена релизная сборка.
