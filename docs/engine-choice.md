## Решение для Ноны

На Android используем **Xray-core через libXray** для обоих протоколов. Он поддерживает VLESS+REALITY и совместимый Hysteria2 outbound с QUIC, TLS и FinalMask. Hysteria2 проверен с действующим сервером VDSina на реальном Android-устройстве; решение использовать одно ядро основано на этом тесте и [документации Xray](https://xtls.github.io/en/config/transports/hysteria.html). Для остальных платформ интеграция ещё не завершена.

`engine_profiles.dart` готовит профили в памяти. Клиент не записывает их в обычные настройки, не показывает в UI и не содержит реальных адресов или credentials в исходниках. Подписанный пакет версии 3 содержит зашифрованные для устройства данные VLESS+REALITY и Hysteria2. При нажатии «Подключить» клиент пробует Hysteria2, затем VLESS для каждого узла по порядку подписанного списка. Неудачный запуск закрывает туннель до следующей попытки. Ранее на Android проверен сценарий с искусственно недоступным Hysteria2: клиент автоматически подключил VLESS. После последнего обновления пакета оба протокола завершились таймаутом проверки трафика, а в Happ на ПК не проходит пинг ссылок. Текущее состояние VPN-транспорта требует отдельной диагностики. Проверка доступности при работающем туннеле и автоматическая замена после его обрыва ещё не реализованы.

На Android включена [libXray v26.10.31](https://github.com/XTLS/libXray/releases/tag/v26.10.31). `NonaVpnService` проверяет профиль, применяет исключения приложений, передаёт TUN fd ядру и выводит исходящие сокеты ядра из туннеля через системный `protect()`. После запуска он проверяет прохождение HTTPS-запроса через VPN, затем сообщает «подключён». Кнопка «Отключить» останавливает ядро и закрывает TUN. В тесте 10 ноября 2026 года браузер на Android показал выходной IP VDSina `195.63.146.49` через Hysteria2, а после отключения Android удалил VPN-сеть. На Apple нужен Packet Tunnel extension, для Windows — системный TUN/adapter.

Android-служба готовит маршруты IPv4 и IPv6 для всего трафика, кроме выбранных приложений. Выбранное приложение MAX исключено из системной VPN-сети по UID в проверке Android. Прямые маршруты по российским доменам и адресам, расширенные проверки DNS/IPv6 утечек и длительная проверка стабильности ещё нужны. VLESS+REALITY с отпечатком `chrome` не прошёл проверку на телефоне по Wi-Fi и мобильной сети. С `safari` два последовательных подключения по Wi-Fi и одно по мобильной сети прошли, а браузер показал IP VDSina. Это эмпирический результат, не доказательство конкретной причины блокировки `chrome`.

Лицензии исходных проектов различаются: [Xray-core — MPL-2.0](https://github.com/XTLS/Xray-core/blob/main/LICENSE), [официальный Hysteria 2 — MIT](https://github.com/HyNetworks/hysteria/blob/master/LICENSE.md), [libXray wrapper — MIT](https://github.com/XTLS/libXray), а [v2rayN](https://github.com/2dust/v2rayN) и [v2rayNG](https://github.com/2dust/v2rayNG) — GPL-3.0. Поэтому Нона использует ядра и собственный код интеграции, а не копирует код этих приложений. Перед распространением бинарников нужно выполнить требования лицензий всех включённых зависимостей.

## Что проверить следующим

1. Получить исходники или APK RefLab VPN и установить точный состав движков конкретной сборки; текущий README этих сведений не содержит.
2. Проверить VLESS+REALITY в длительной работе и отслеживать изменения поведения сети и ядра.
3. Добавить контроль связи во время работы, переключение на VLESS и затем на другой узел, не допуская неожиданного прямого выхода трафика.
4. Проверить автоматическую выдачу и отзыв индивидуальных credentials на новом аккаунте, затем подключить AdminVPS/Aeza.
