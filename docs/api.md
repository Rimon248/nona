# Контракт control API

На домашнем сервере включён OIDC-режим. Персональные маршруты требуют `Authorization: Bearer <access_token>` от отдельного Keycloak Ноны. API проверяет подпись, issuer, audience, client ID и срок действия; запрос с чужим или просроченным токеном получает `401`. Ответы с персональными данными имеют `Cache-Control: no-store`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/v1/info` | Версия API, режим входа и флаг провижининга; без токена |
| GET | `/v1/account` | Создаёт связь Keycloak `sub` с локальным аккаунтом при первом входе; возвращает `account_id` |
| POST | `/v1/devices` | Регистрирует устройство с публичным X25519-ключом |
| GET | `/v1/devices` | Список устройств аккаунта, включая отозванные |
| GET | `/v1/devices/{id}/configuration` | Подписанный пакет активному устройству владельца |
| DELETE | `/v1/devices/{id}` | Отзывает устройство и удаляет сохранённый пакет |

`POST /v1/devices` принимает `{"label":"Телефон","public_key":"<base64url без padding>"}`. Ключ должен быть 32-байтным публичным X25519; приватный остаётся на устройстве. Лимит — восемь активных устройств на аккаунт. Повтор ключа возвращает `409`. Для чужого, отозванного, отсутствующего или просроченного пакета ответ одинаковый — `404`.

Пакет содержит версию, срок, владельца, устройство, узлы, зашифрованные credentials и подпись Ed25519. Клиент проверяет подпись и возрастающую версию до сохранения. Пример без рабочих секретов находится в `test-vectors/config-bundle.json`. `provisioning_enabled=false` означает, что публичный API не создаёт VPN credentials автоматически. Операторские команды `provision-device` и `retire-device` создают и отзывают персональный доступ на VDSina.

Маршруты `/v1/sessions*` доступны только в локальном режиме разработки и на домашнем сервере выключены. `/readyz` доступен лишь внутри Docker-сети.
