# Контракт control API

Все пути `/v1/*` с персональными данными доступны только по HTTPS. Исключения: `GET /healthz` для локальной диагностики и `GET /v1/info` без секретов. Текущий сервер реализует только эти два GET; `provisioning_enabled=false`. Формат подписанного пакета и проверка подписи реализованы как независимые модули, но endpoint выдачи ещё не подключён.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/sessions` | Вход; выдаёт короткий access token и вращаемый refresh token |
| POST | `/v1/sessions/refresh` | Обновляет пару токенов; повторное использование старого refresh token отзывает семейство |
| DELETE | `/v1/sessions/current` | Выход и отзыв текущей сессии |
| POST | `/v1/devices` | Регистрирует устройство с публичным ключом устройства |
| GET | `/v1/configuration` | Подписанный, индивидуальный пакет с `version`, `expires_at`, `nodes`, `rules` |
| GET | `/v1/configuration/version` | Лёгкая проверка наличия обновления без выдачи секретов |
| DELETE | `/v1/devices/{id}` | Отзыв устройства и его credentials |

У пакета есть строгий номер версии и срок действия. Транспортные credentials будут выдаваться только после аутентификации и проверки принадлежности устройства. Сервер не должен отдавать чужие credentials даже по известному ID. Подпись Ed25519 покрывает байты канонического JSON payload с префиксом `NONA-CONFIG-BUNDLE-v1\0`, включая пользователя, устройство, версию, срок и список узлов. Публичные ключи проверки должны поставляться с клиентом или через заранее доверенный канал; приватный ключ остаётся на домашнем сервере. Ротация ключа требует отдельной процедуры.

Конверт ответа содержит `key_id`, `payload_b64` и `signature` в base64url без padding. После декодирования `payload_b64` получается структура **без действующих данных**:

```json
{
  "schema_version": 1,
  "account_id": "account-id-from-server",
  "version": 42,
  "device_id": "device-id-from-server",
  "expires_at": "2026-12-01T00:00:00Z",
  "nodes": [
    {
      "id": "vdsina-primary",
      "provider": "vdsina",
      "endpoint": "example.invalid",
      "transports": ["vless-reality", "hysteria2"],
      "encrypted_credentials": "encrypted-device-specific-payload"
    }
  ],
  "rules_version": 7
}
```

Реальный порядок полей при подписи задаёт серверная структура, а не этот поясняющий пример. Общий тестовый пакет в `test-vectors/config-bundle.json` проверяется кодом Go и Flutter; он содержит только вымышленные значения. Это пока не готовая конфигурация sing-box. Шифрование credentials для конкретного устройства, генерация ключей устройств, сертификат API и ротация должны быть реализованы до включения выдачи. Подпись без шифрования не скрывает credentials от процессов с доступом к памяти устройства.
