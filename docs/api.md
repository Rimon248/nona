# Контракт control API (проект, ещё не реализован)

Все пути `/v1/*` доступны только по HTTPS. Исключения: `GET /healthz` для локальной диагностики и `GET /v1/info` без секретов. Текущий сервер реализует только эти два GET; `provisioning_enabled=false`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/sessions` | Вход; выдаёт короткий access token и вращаемый refresh token |
| POST | `/v1/sessions/refresh` | Обновляет пару токенов; повторное использование старого refresh token отзывает семейство |
| DELETE | `/v1/sessions/current` | Выход и отзыв текущей сессии |
| POST | `/v1/devices` | Регистрирует устройство с публичным ключом устройства |
| GET | `/v1/configuration` | Подписанный, индивидуальный пакет с `version`, `expires_at`, `nodes`, `rules` |
| GET | `/v1/configuration/version` | Лёгкая проверка наличия обновления без выдачи секретов |
| DELETE | `/v1/devices/{id}` | Отзыв устройства и его credentials |

У пакета есть строгий номер версии и срок действия. Транспортные credentials выдаются только после аутентификации и проверки принадлежности устройства. Сервер не должен отдавать чужие credentials даже по известному ID. Подпись покрывает байты канонического payload, включая пользователя, устройство, версию, срок и список узлов; ключ проверки вшит в клиент, а ключ подписи остаётся на домашнем сервере. Ротация ключа требует заранее определённой процедуры.

Пример **структуры без действующих данных**:

```json
{
  "schema_version": 1,
  "version": 42,
  "device_id": "device-id-from-server",
  "expires_at": "2026-12-01T00:00:00Z",
  "nodes": [
    {
      "id": "vdsina-primary",
      "provider": "vdsina",
      "endpoint": "example.invalid",
      "transports": ["vless-reality", "hysteria2"],
      "credentials": "encrypted-device-specific-payload"
    }
  ],
  "rules_version": 7,
  "signature": "base64-signature-placeholder"
}
```

Это контракт для следующего этапа, не готовая конфигурация sing-box. Формат шифрования payload, генерация ключей устройств, сертификат API, ротация и сериализация подписи должны быть зафиксированы перед реализацией клиента и сервера вместе. Простая подпись без шифрования не скрывает credentials от других процессов с доступом к памяти устройства.
