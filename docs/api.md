# Контракт control API

Все пути `/v1/*` с персональными данными доступны снаружи только по HTTPS. Исключения: `GET /healthz` для локальной диагностики и `GET /v1/info` без секретов. При подключённой PostgreSQL сервер реализует вход, обновление токенов, выход, учёт устройств и выдачу заранее установленного пакета устройству владельца. `provisioning_enabled=false`: создание VPN credentials на узлах ещё не подключено.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/sessions` | Вход; выдаёт `account_id`, короткий access token и вращаемый refresh token |
| POST | `/v1/sessions/refresh` | Обновляет `account_id` и пару токенов; повторное использование старого refresh token отзывает семейство |
| DELETE | `/v1/sessions/current` | Выход и отзыв текущей сессии |
| POST | `/v1/devices` | Регистрирует устройство с публичным ключом устройства |
| GET | `/v1/devices` | Список устройств текущего аккаунта, включая отозванные |
| GET | `/v1/devices/{id}/configuration` | Подписанный пакет только для активного устройства текущего аккаунта |
| DELETE | `/v1/devices/{id}` | Помечает устройство отозванным; действующих VPN credentials пока нет |

Маршруты устройств уже реализованы. Для `POST`, `GET` и `DELETE` требуется `Authorization: Bearer <access_token>`. `POST /v1/devices` принимает JSON `{"label":"Телефон","public_key":"<base64url без padding>"}` и возвращает `201` с `id`, `label`, `public_key`, `created_at`, `revoked_at`. Ключ должен быть 32-байтным публичным X25519; приватный ключ остаётся на устройстве. Лимит — восемь активных устройств на аккаунт. Повторная регистрация того же ключа возвращает `409`; отозванный ключ повторно не используется. `GET` возвращает массив устройств. `DELETE` возвращает `204` либо `404`, в том числе для чужого устройства. После выхода из аккаунта локальный ключ устройства сохраняется для повторного входа; выход отзывает текущую сессию. Этот этап не выпускает и не отзывает credentials на VPN-узле.

Получение конфигурации требует `Authorization: Bearer <access_token>`. Отсутствующий, чужой, отозванный или просроченный пакет возвращает одинаковый `404`; ответ имеет `Cache-Control: no-store`. Пакет загружается в базу только через доверенный локальный операторский путь или будущий provisioner после проверки подписи, принадлежности устройству, срока и монотонной версии. Отзыв устройства удаляет сохранённый пакет, но отзыв ранее выданных credentials на самом VPN-узле ещё не реализован.

У пакета есть строгий номер версии и срок действия. Транспортные credentials будут выдаваться только после аутентификации и проверки принадлежности устройства. Сервер не должен отдавать чужие credentials даже по известному ID. Подпись Ed25519 покрывает байты канонического JSON payload с префиксом `NONA-CONFIG-BUNDLE-v1\0`, включая пользователя, устройство, версию, срок и список узлов. Публичные ключи проверки должны поставляться с клиентом или через заранее доверенный канал; приватный ключ остаётся на домашнем сервере. Ротация ключа требует отдельной процедуры.

Конверт ответа содержит `key_id`, `payload_b64` и `signature` в base64url без padding. После декодирования `payload_b64` получается структура **без действующих данных**:

```json
{
  "schema_version": 1,
  "account_id": "account-id-from-server",
  "version": 42,
  "device_id": "device-id-from-server",
  "expires_at": "2026-12-01T00:00:00Z",
  "nodes": [
    {
      "id": "vdsina-primary",
      "provider": "vdsina",
      "endpoint": "example.invalid",
      "transports": ["vless-reality", "hysteria2"],
      "encrypted_credentials": "encrypted-device-specific-payload"
    }
  ],
  "rules_version": 7
}
```

Реальный порядок полей при подписи задаёт серверная структура, а не этот поясняющий пример. Общий тестовый пакет в `test-vectors/config-bundle.json` проверяется кодом Go и Flutter; он содержит только вымышленные значения. Это пока не готовая конфигурация Xray или Hysteria 2. Серверное шифрование для зарегистрированного ключа и клиентская расшифровка проверены отдельным вымышленным примером `test-vectors/credential-box.json`; формат описан в `credential-encryption.md`. Автоматическое создание пакета и доступа на узле, сертификат сервера, ротация и отзыв credentials ещё нужны до реального использования. Подпись и шифрование не скрывают данные от ОС, самого приложения и процессов с доступом к его памяти.
