# Шифрование данных доступа для устройства

Серверный модуль `internal/credentials` шифрует данные доступа для 32-байтного публичного X25519-ключа зарегистрированного устройства. Клиентский `credential_box.dart` использует локальный закрытый ключ, созданный при регистрации. Общий вымышленный пример в `test-vectors/credential-box.json` проверяет совместимость Go и Flutter; его тестовый закрытый ключ никогда не используется для реального доступа.

Формат поля `encrypted_credentials`: `v1.<ephemeral_public>.<nonce>.<ciphertext_and_tag>`. Бинарные части кодируются base64url без padding. Для каждого шифрования сервер создаёт новый временный X25519-ключ и 12-байтный nonce из криптографического генератора. Общий секрет X25519 поступает в HKDF-SHA256 с salt `NONA-CREDENTIALS-v1`, output length 32 и info, равным контексту ниже. Полученный ключ используется AES-256-GCM; последние 16 байт ciphertext — тег. Максимальный размер открытых данных — 4096 байт.

Контекст для HKDF и AEAD AAD — UTF-8 байты `NONA-CREDENTIALS-v1\0<account_id>\0<device_id>\0<node_id>\0<bundle_version>`. Пустые и содержащие NUL идентификаторы отвергаются. Изменение пользователя, устройства, узла, версии или зашифрованных байтов делает расшифровку невозможной. Сервер отказывается подписывать пакет с открытым текстом или повреждённым форматом в поле `encrypted_credentials`; клиент тоже отвергает такой пакет. Клиент сначала проверяет подпись, принадлежность и срок действия всего пакета, затем открывает данные выбранного узла только в памяти. Открытый текст не сохраняется в обычные настройки.

Эта схема защищает содержимое credentials при хранении и выдаче для конкретного устройства, но **не скрывает** ID узла, провайдера и `endpoint`: они находятся в подписанном пакете вне шифрованного поля. Сам пакет хранится через защищённое хранилище ОС и передаваться должен только по HTTPS. Доступ с правами ОС, модифицированное устройство, дамп памяти и сетевые признаки VPN остаются вне этой гарантии. До публичного использования нужны независимая проверка протокола, ротация ключей, безопасный отзыв credentials на узлах и тесты на реальных устройствах.

## Данные внутри зашифрованного поля

Клиент понимает UTF-8 JSON `schema_version: 2` с полями `vless_reality` и `hysteria2`. Отсутствующий транспорт задаётся `null`. Список `transports` подписанного узла должен точно совпадать с непустыми разделами, а `host` каждого раздела — с подписанным `endpoint`; лишние поля и неверные значения отклоняются. Это не ссылка подписки: параметры передаются движку только после проверки подписи пакета, расшифрования для устройства и проверки формата.

```json
{
  "schema_version": 2,
  "vless_reality": {
    "host": "node.example.invalid",
    "port": 8443,
    "user_id": "00000000-0000-4000-8000-000000000001",
    "server_name": "front.example.invalid",
    "reality_password": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
    "encryption": "mlkem768x25519plus.native.1rtt.AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA",
    "short_id": "a1b2c3d4",
    "flow": "xtls-rprx-vision"
  },
  "hysteria2": {
    "host": "node.example.invalid",
    "port": 443,
    "auth": "fictional-test-password",
    "server_name": "node.example.invalid",
    "obfs_password": "fictional-salamander-password"
  }
}
```

В примере только вымышленные значения. Серверный `configbundle.BuildForDevice` проверяет согласованность адреса и транспортов, шифрует документ для публичного ключа зарегистрированного устройства и подписывает пакет. `NodeAccess` преобразует проверенные данные в профили Xray и Hysteria2 в памяти, а исходный буфер расшифрованных байтов очищает после разбора. Тестовая Android-сборка принимает персональный пакет и подключает оба протокола через VDSina.
`obfs_password` задаёт пароль Salamander для Hysteria2; `null` означает отсутствие обфускации. Значение должно совпадать с настройкой сервера. Формат сверён с [официальной конфигурацией клиента Hysteria 2](https://v2.hysteria.network/docs/advanced/Full-Client-Config/).
