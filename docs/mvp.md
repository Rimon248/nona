# Реалистичный MVP

| Этап | Платформы | Результат | Проверка |
|---|---|---|---|
| 0. Каркас (сейчас) | Все четыре | Общий UI, запуск control API, схема, выбор узла, проверка подписи и хранилище проверенного пакета | `flutter analyze`, `flutter test`, `go test ./...` |
| 1. Сервер аккаунтов (частично) | Все четыре | Отдельный Keycloak Ноны, API и защищённая панель доступны по публичному HTTPS; клиент использует OIDC/PKCE. Самостоятельная регистрация без письма и появление ожидающего аккаунта в панели проверены временным пользователем 11 ноября. Панель управляет доступом и ролями администратора. На Android проверены вход `roman`, регистрация устройства и восстановление после перезапуска. Проверка самих кнопок одобрения и аудит ещё нужны | Новый аккаунт виден в панели и не получает конфигурацию до разрешения; отзыв прекращает выдачу |
| 2. Провижининг VDSina (частично) | Все четыре | Операторские команды создают и отзывают персональные credentials VLESS и Hysteria2; серверная служба каждые 15 секунд обрабатывает разрешённые устройства и отзыв доступа. Выдача и отзыв для нового временного аккаунта проверены без включения VPN. Неудачные попытки теперь откладываются на 1–15 минут. Ротация по сроку есть; восстановление после сбоя и кнопки решений панели ещё не проверены | Выдача и отзыв без ручной раздачи ссылок; проверить действия панели и восстановление после сбоя |
| 3. Android (в работе) | Android | `VpnService`, libXray, защищённое хранение, IPv4/IPv6, DNS и исключения приложений. Оба протокола ранее работали на Samsung, но текущая повторная проверка завершилась таймаутом. Мониторинг и переключение при обрыве ещё нужны | После восстановления транспорта: прямое приложение, зарубежный адрес через VPN, DNS/IPv6, отказ Hysteria2 и переход на другой узел |
| 4. Настольный TUN (в работе) | macOS, Windows | Xray через `utun` и Wintun; те же аккаунты и персональные узлы, запрос системных прав, защищённое хранилище, ручное отключение | Сборка в GitHub Actions; на реальных Mac и Windows проверить вход, выходной IP, DNS/IPv6, отключение, восстановление после сбоя |
| 5. iOS | iOS | Packet Tunnel extension, entitlement, Keychain, системные маршруты и обновления | Реальное устройство, подпись и установка; Wi-Fi и мобильная сеть |
| 6. Дополнительные узлы | Все четыре | AdminVPS и Aeza через тот же provisioner; выбор и failover | Отказ каждого узла не ломает рабочую сессию на другом |

Android стал первой платформой для сквозной проверки. Следующий порядок выбран владельцем проекта: Windows и macOS в режиме TUN, затем iOS; режим системного прокси добавим после всех четырёх платформ. iOS с собственным Packet Tunnel extension требует Apple Developer signing и Network Extension entitlement. Настольные сборки не считаются готовыми без проверки на устройствах.

## Критерии первого рабочего релиза

- Один пользователь входит на Android и получает собственные VLESS+REALITY и Hysteria2 credentials без ручной ссылки.
- Выход из аккаунта удаляет локальные токены и конфигурацию, отзывает refresh token; отдельное удаление устройства удаляет его локальный ключ и отзывает credentials на узле.
- Обновление набора узлов проходит только после проверки подписи и не портит последнюю рабочую конфигурацию при сбое.
- При подключении клиент сначала проверяет Hysteria2, затем VLESS на том же узле, затем другой узел. После обрыва действующего туннеля переключение не выпускает трафик напрямую, если выбрана защита от утечек.
- Российские тестовые домены/IP и явно исключённые Android-приложения идут напрямую; зарубежные тестовые адреса — через VPN. IPv4, IPv6 и DNS проверяются отдельно.
- Системное разрешение VPN, статус и ограничения видимости описаны пользователю без обещания скрытности.

## Что потребуется от оператора перед интеграцией

Доступ к домашнему серверу и его публичному HTTPS-имени; способ администрирования существующего VDSina-узла; фактические порты и версии серверных компонентов; тестовые Android/iOS/macOS/Windows устройства; Apple Developer account для iOS Packet Tunnel. Эти значения передаются через защищённый канал и не помещаются в репозиторий или чатовые примеры.
