# Настольная Нона: пробная TUN-сборка

На Windows и macOS Нона входит через тот же аккаунт, проверяет подписанную конфигурацию устройства и пробует Hysteria2, затем VLESS+REALITY на каждом выданном узле. Десктопный режим использует системный TUN Xray. Режим системного прокси запланирован после iOS. Раздел «Интернет без VPN» с исключением отдельных приложений пока работает только на Android; настольный TUN направляет в VPN весь интернет-трафик, кроме частных адресов локальной сети. На Windows и Android приложение переключает узел после двух подряд ошибок проверки; на macOS переключение работает при первоначальном подключении.

## macOS

`apps/client/build-macos-release.sh` загружает проверенную по SHA-256 универсальную сборку Xray и создаёт `apps/client/build/macos/Build/Products/Release/Nona.app`. Сейчас Нона использует стандартный системный запрос администратора при запуске и остановке TUN: Xray создаёт `utun`, а Нона временно задаёт системные DNS-серверы и возвращает прежние при отключении. Эти запросы не управляются разрешениями «Полный доступ к диску» или «Управление компьютером». Чтобы убрать пароль при каждом подключении, нужен привилегированный LaunchDaemon через `SMAppService`; пользователь одобряет его один раз в **Основные → Объекты входа и расширения**, после чего Нона обращается к нему для запуска и остановки. Такой помощник ещё не реализован. Apple требует стабильную подпись приложения и помощника для их безопасного сопряжения и обновления; GitHub preview сейчас ad-hoc подписан, стабильной подписи у владельца проекта пока нет. См. [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) и [Apple guide для LaunchDaemon](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos).

На Flutter 3.47.9 выпускная компиляция может остановиться с `Class with illegal cid` в `_window_macos.dart`. Задание GitHub Actions применяет ограниченный [обход известной ошибки Flutter](https://github.com/flutter/flutter/issues/191575) к временной копии SDK перед сборкой; исходники Ноны и установленный у пользователя Flutter он не меняет.

Apple Developer Program для этой локальной TUN-сборки не требуется. Приложение подписывается локальной ad-hoc подписью, поэтому macOS может запросить ручное разрешение на запуск загруженного архива. Для распространения с обычной проверкой Gatekeeper позднее понадобится Developer ID и нотариализация. Данные аккаунта и подписанные пакеты хранятся в Keychain без возможности общего доступа с другими приложениями.

Пробная ad-hoc подпись меняется при пересборке. Из-за этого macOS может снова запросить доступ после обновления. Нона хранит логические секреты в одной защищённой записи Связки ключей вместо отдельной записи для каждого поля. При первом запуске после обновления старые записи переносятся по мере чтения, поэтому macOS ещё может запросить доступ к старым данным; в окне Связки ключей выберите «Разрешать всегда» для этой сборки. Новая сборка с другой подписью может запросить доступ повторно. Для постоянного доверия между сборками нужна стабильная подпись. Публичный выпуск потребует Developer ID и нотариализацию. Разрешение Связки ключей отдельно от разрешения администратора: оно не даёт права запускать системный туннель.

Вход на Mac открывает системное окно авторизации macOS для сайта Ноны. После успешного входа оно закрывается и управление возвращается в приложение. Страница входа и пароль остаются под управлением системного браузера; адрес `127.0.0.1`, использовавшийся в ранней пробной сборке, был только локальным адресом возврата из браузера, а не сервером аккаунтов.

## Windows

`apps/client/build-windows-release.ps1` загружает libXray, Xray-core и Wintun с проверкой SHA-256 и создаёт папку `apps/client/build/windows/x64/runner/Release`. Распространять и переносить нужно **всю папку**, а не один `.exe`. Windows запрашивает повышение прав при запуске Ноны, поскольку TUN меняет системные маршруты и правила Windows Filtering Platform. Пока меню трея не подготовлено, закрытие окна штатно отключает VPN и полностью завершает Нону.

В архив вместе с программой копируются три библиотеки Visual C++ из среды сборки: `msvcp140.dll`, `vcruntime140.dll` и `vcruntime140_1.dll`. Это позволяет запустить пробную сборку на Windows без ранее установленного Visual C++ Redistributable. Для будущего установщика можно использовать системный пакет Microsoft, который обновляется отдельно от Ноны.

Проверка задержки измеряет время HTTPS-ответа через активный TUN, а не ICMP до VPN-сервера. Отказ одного сайта проверки больше не переводит работающий туннель в состояние «канал недоступен»: Нона оставляет подключение активным и показывает предупреждение отдельно. Две последовательные ошибки проверки канала запускают переключение на Windows и Android, пока приложение работает. macOS сейчас переключает узел только при первоначальном подключении; фоновый мониторинг не включён из-за системных запросов администратора при повторном запуске TUN.

## Получение пробных сборок

После успешного запуска GitHub Actions **Desktop preview** скачайте артефакт нужной системы со страницы запуска. Эти архивы пока не являются выпуском GitHub Release. В Mac-предыдущей сборке проверялись вход, TUN через VDSina, HTTPS и возврат маршрута/DNS при отключении; текущую сборку с двумя узлами и изменениями подключения ещё нужно проверить. В Windows 11 Parallels подтверждены запуск, вход и регистрация устройства. Подключение отображается активным и проверка Cloudflare проходит, но браузер получает `ERR_CONNECTION_CLOSED` на сайтах. Из домашней проверки VDSina следует, что его IPv4 egress работает, а IPv6 egress отсутствует. Windows TUN теперь использует только IPv4; `misconfigtun` должен блокировать IPv6 при активном туннеле, чтобы он не ушёл напрямую. Это диагностическая правка; её результат нужно проверить на Windows. Проверьте реальные сайты, Hysteria2→VLESS, переключение VDSina→Aeza и штатное отключение прежде чем публиковать сборку.
