# Настольная Нона: ранние TUN-выпуски

На Windows и macOS Нона входит через тот же аккаунт, проверяет подписанную конфигурацию устройства и пробует Hysteria2, затем VLESS+REALITY на каждом выданном узле. Десктопный режим использует системный TUN Xray. Режим системного прокси запланирован после iOS. Раздел «Интернет без VPN» теперь доступен на настольных системах для сайтов; Windows также поддерживает правила по запущенным программам. На Windows и Android приложение переключает узел после двух подряд ошибок проверки; на macOS переключение работает при первоначальном подключении.

## Маршрутизация сайтов и программ

На новой установке зоны `.ru`, `.рф`, `.su`, `.moscow`, `.tatar` и `.москва` выбраны для прямого соединения. Можно выключить каждую зону, добавить свой домен напрямую или указать исключение, которое должно идти через VPN даже внутри выбранной зоны. Собственный выбор хранится локально в настройках приложения без VPN-конфигураций и применяется при следующем подключении. Xray определяет домен из доступного HTTP/TLS/QUIC имени и оставляет полученный системой IP назначения. Поэтому собственный защищённый DNS программы, скрытое TLS-имя и подключение по IP могут помешать правилу сайта; надпись «Все сайты в зоне» описывает область правила, а не гарантирует обнаружение любого соединения.

На Windows список «Приложения мимо VPN» показывает имена `.exe` приложений с открытым окном; можно добавить имя вручную, если программа работает в фоне или закрыта. Кнопки «Выбрать все» и «Снять все выделения» применяются к выбору приложений на этом компьютере. Выбранное имя передаётся в правило `process` ядра Xray и имеет приоритет над правилами сайтов. Совпадение по имени охватывает все процессы с таким именем, поэтому для разных программ с одинаковым `.exe` понадобится точное правило по пути в следующей версии. Системные процессы и ядро Ноны исключены из выбора. На macOS Xray не поддерживает сопоставление TUN-соединения с процессом, поэтому надёжного переключателя для отдельной программы здесь пока нет. Правила сайтов на Mac работают по доступному имени домена.

Для проверки: подключитесь, откройте `wwhois.ru` при включённой зоне `.ru`, затем выключите зону и переподключитесь; внешний адрес должен смениться с обычной сети на VPN. На Windows можно отдельно отметить браузер в «Программы напрямую», переподключиться и сравнить его внешний адрес с неотмеченным состоянием. `2ip.ru` уже давал таймаут и без VPN, поэтому не годится как единственный тест.

## macOS

`apps/client/build-macos-release.sh` загружает проверенную по SHA-256 универсальную сборку Xray, компилирует помощник для Intel и Apple Silicon и упаковывает его в `Nona.app`. На macOS 13 и новее Нона предлагает зарегистрировать узкий LaunchDaemon через `SMAppService`; пользователь одобряет его в **Основные → Объекты входа и расширения → Разрешить в фоновом режиме**. После одобрения помощник выполняет только проверку профиля Xray, подключение/отключение TUN и временную замену DNS, так что повторные запросы пароля администратора для этих операций не нужны. На macOS 12 и при неактивном помощнике остаётся прежний системный запрос.

GitHub preview и ранний desktop-релиз подписаны ad-hoc. Они содержат helper, но macOS не разрешает зарегистрировать его с такой подписью. Для локальной проверки создайте в «Связке ключей» постоянную self-signed identity типа Code Signing и соберите приложение с `NONA_MACOS_SIGNING_IDENTITY="имя identity"`. Используйте одну и ту же identity при каждой локальной сборке, иначе macOS будет считать новый helper другим приложением. Публичный выпуск следует подписывать постоянным сертификатом Apple Developer ID и нотариализовать; для этого потребуется Apple Developer Program. [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) позволяет регистрировать и отслеживать состояние launch daemon, а [Apple описывает запуск bundled helper через этот механизм](https://developer.apple.com/documentation/servicemanagement/updating-helper-executables-from-earlier-versions-of-macos).

На Flutter 3.47.9 выпускная компиляция может остановиться с `Class with illegal cid` в `_window_macos.dart`. Задание GitHub Actions применяет ограниченный [обход известной ошибки Flutter](https://github.com/flutter/flutter/issues/191575) к временной копии SDK перед сборкой; исходники Ноны и установленный у пользователя Flutter он не меняет.

Apple Developer Program не требуется для ad-hoc preview или локальной self-signed identity. Ad-hoc архив может потребовать ручного разрешения macOS на запуск и не может зарегистрировать LaunchDaemon. Для публичного распространения с обычной проверкой Gatekeeper понадобятся Developer ID и нотариализация. Данные аккаунта и подписанные пакеты хранятся в Keychain без возможности общего доступа с другими приложениями.

Запросы Связки ключей и запросы администратора — разные вещи. LaunchDaemon устраняет повторную авторизацию для системного туннеля, но не меняет доступ `flutter_secure_storage_service` к Keychain. Для доступа к ранее сохранённым данным можно выбрать «Разрешать всегда»; стабильная подпись также нужна, чтобы Keychain узнавал новую версию как ту же программу. Это разрешение не даёт приложению права менять системные маршруты.

Вход на Mac открывает системное окно авторизации macOS для сайта Ноны. После успешного входа оно закрывается и управление возвращается в приложение. Страница входа и пароль остаются под управлением системного браузера; адрес `127.0.0.1`, использовавшийся в ранней пробной сборке, был только локальным адресом возврата из браузера, а не сервером аккаунтов.

## Windows

`apps/client/build-windows-release.ps1` загружает libXray, Xray-core и Wintun с проверкой SHA-256 и создаёт папку `apps/client/build/windows/x64/runner/Release`. Распространять и переносить нужно **всю папку**, а не один `.exe`. В «Приложения мимо VPN» список для массового выбора включает программы с открытым окном; фоновые программы можно добавить вручную по имени `.exe`. Windows запрашивает повышение прав при запуске Ноны, поскольку TUN меняет системные маршруты и правила Windows Filtering Platform. Пока меню трея не подготовлено, закрытие окна штатно отключает VPN и полностью завершает Нону.

В архив вместе с программой копируются три библиотеки Visual C++ из среды сборки: `msvcp140.dll`, `vcruntime140.dll` и `vcruntime140_1.dll`. Это позволяет запустить пробную сборку на Windows без ранее установленного Visual C++ Redistributable. Для будущего установщика можно использовать системный пакет Microsoft, который обновляется отдельно от Ноны.

Проверка задержки измеряет время HTTPS-ответа через активный TUN, а не ICMP до VPN-сервера. В Windows Нона больше не запускает отдельную проверку сайта из Flutter: она давала ложную ошибку, хотя тот же сайт открывался в браузере. Работу Windows проверяйте в браузере; статус туннеля и HTTPS-задержка остаются доступны в приложении. Две последовательные ошибки проверки канала запускают переключение на Windows и Android, пока приложение работает. macOS сейчас переключает узел только при первоначальном подключении; фоновый мониторинг не включён.

## Получение настольных выпусков

После отправки тега `desktop-v<версия>` GitHub Actions собирает и публикует Windows и macOS архивы как ранний выпуск. Ограничения ad-hoc подписи macOS описаны в `docs/desktop-release-notes.md`. Задание **Desktop preview** остаётся для пробных сборок из ветки `main`.
