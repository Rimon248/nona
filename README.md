# Виртуальный Помощник Нона

Ранний каркас кроссплатформенного VPN-клиента. Сейчас репозиторий содержит Flutter-приложение для Android, iOS, Windows и macOS, вход в аккаунт через HTTPS, регистрацию устройства с локальным ключом и проверку подписанных обновлений. Сервер выдаёт заранее установленный подписанный пакет только его устройству; клиент автоматически проверяет и сохраняет обновление. Android-сборка включает Xray-core и VPN-службу. **Автоматическое создание доступа на VDSina и рабочее VPN-подключение пока не реализованы.** Никакие действующие ключи, ссылки подписки или сертификаты не включены.

## Состав

- `apps/client` — общий интерфейс Flutter, вход в аккаунт, регистрация устройства, проверка подписанных конфигураций, защищённое хранение, выбор узла, экран выбора прямых приложений Android и нативная Xray-служба Android.
- `services/control-api` — сервер аккаунтов, сессий, устройств и пакетов конфигурации с PostgreSQL. По умолчанию слушает только `127.0.0.1:8080`; создание VPN credentials на узлах ещё не подключено.
- `docs/architecture.md` — компоненты, безопасность и границы возможностей ОС.
- `docs/engine-choice.md` — проверка ядер Happ/v2rayN/v2rayNG и выбор Xray плюс Hysteria 2 для Ноны.
- `docs/mvp.md` — этапы реализации и критерии приёмки.
- `docs/api.md` — действующие маршруты аккаунтов и выдачи заранее установленных конфигураций.
- `docs/backend.md` — запуск аккаунтов на домашнем сервере.
- `deploy/home` — подготовка для существующего Caddy на домашнем сервере: отдельный домен, systemd-служба и проверки перед публикацией.
- `docs/credential-encryption.md` — формат шифрования данных доступа для устройства.
- `docs/privacy-and-threats.md` — видимость VPN и границы защиты от других приложений.
- `docs/app-routing.md` — что видно приложению при прямом и VPN-маршруте.
- `test-vectors` — вымышленные пакеты подписи и шифрования для проверки совместимости Go и Flutter.
- `third_party` — происхождение Android-библиотеки Xray и тексты лицензий.

## Локальный запуск

```sh
cd apps/client
flutter run
```

Для подключения к собственному серверу аккаунтов задайте HTTPS-адрес при сборке: `flutter run --dart-define=NONA_API_BASE_URL=https://example.invalid`. Для получения конфигурации дополнительно задайте заранее доверенные публичные `NONA_CONFIG_KEY_ID` и `NONA_CONFIG_VERIFY_KEY_B64`; без них клиент откажется принимать обновления. Пароли, токены, закрытый ключ подписи и IP VPN-узла в параметры сборки не добавляйте.

```sh
cd services/control-api
go test ./...
go run ./cmd/api
```

Публиковать API в интернет пока нельзя: автоматическое создание и отзыв VPN credentials, HTTPS reverse proxy и эксплуатационная защита ещё не готовы. Для домашнего сервера потребуется постоянный адрес или домен и продуманное поведение при недоступности дома. Порядок настройки аккаунтов — в `docs/backend.md`.
