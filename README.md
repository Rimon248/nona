# Виртуальный Помощник Нона

Ранний кроссплатформенный VPN-клиент. Flutter-приложение входит через отдельный Keycloak Ноны, регистрирует устройство и проверяет подписанные обновления. На Android работает VPN-служба с Xray-core: Hysteria2 и VLESS+REALITY до VDSina проверены на реальном телефоне, выходной адрес обоих — `195.63.146.49`. Кнопка отключения закрывает системный VPN-интерфейс. При активном подключении доступна ручная проверка задержки: три HTTPS-запроса через VPN, на экране показывается средний по порядку результат в миллисекундах. Это время ответа сайта с учётом туннеля, а не ICMP-пинг сервера. Индивидуальные данные доступа выдаёт оператор через домашний сервер; автоматическая выдача новым пользователям ещё не включена. Секреты, ссылки подписки и сертификаты в репозиторий не включены.

## Состав

- `apps/client` — общий интерфейс Flutter, вход в аккаунт, регистрация устройства, проверка подписанных конфигураций, защищённое хранение, выбор узла, экран выбора прямых приложений Android и нативная Xray-служба Android.
- `services/control-api` — API аккаунтов, устройств и пакетов конфигурации с PostgreSQL и проверкой токенов отдельного Keycloak. Операторская команда создаёт и отзывает индивидуальные данные доступа на VDSina; автоматическая очередь выдачи и отзыва пока не включена.
- `docs/architecture.md` — компоненты, безопасность и границы возможностей ОС.
- `docs/engine-choice.md` — проверка ядер Happ/v2rayN/v2rayNG и выбор Xray плюс Hysteria 2 для Ноны.
- `docs/mvp.md` — этапы реализации и критерии приёмки.
- `docs/api.md` — действующие маршруты аккаунтов и выдачи заранее установленных конфигураций.
- `docs/backend.md` — запуск аккаунтов на домашнем сервере.
- `deploy/home` — Docker-размещение для существующего Caddy на домашнем сервере, отдельный домен и проверки перед публикацией.
- `docs/publication.md` — фактическое состояние публичного HTTPS, отдельного Keycloak и панели.
- `docs/credential-encryption.md` — формат шифрования данных доступа для устройства.
- `docs/privacy-and-threats.md` — видимость VPN и границы защиты от других приложений.
- `docs/app-routing.md` — что видно приложению при прямом и VPN-маршруте.
- `test-vectors` — вымышленные пакеты подписи и шифрования для проверки совместимости Go и Flutter.
- `third_party` — происхождение Android-библиотеки Xray и тексты лицензий.

## Локальный запуск

```sh
cd apps/client
flutter run
```

Для подключения к домашнему серверу задайте HTTPS-адрес при сборке: `flutter run --dart-define=NONA_API_BASE_URL=https://nona.server.basketref.ru`. Публичный HTTPS и вход через Keycloak на тестовом Android уже проверены. Для получения конфигурации дополнительно задайте заранее доверенные публичные `NONA_CONFIG_KEY_ID` и `NONA_CONFIG_VERIFY_KEY_B64`; без них клиент откажется принимать обновления. Пароли, токены, закрытый ключ подписи и IP VPN-узла в параметры сборки не добавляйте.

Один аккаунт может использовать несколько устройств. После входа каждое устройство автоматически регистрирует свой ключ и получает отдельные VPN credentials; пользователь не копирует ссылки. Это позволяет отключить потерянное устройство без замены ключей на остальных. Общий ключ на весь аккаунт был бы проще на сервере, но не позволил бы выборочно отзывать доступ.

```sh
cd services/control-api
go test ./...
go run ./cmd/api
```

Отдельные Keycloak и API опубликованы через домашний Caddy. Панель доступна после входа оператора и пока показывает состояние служб; функции управления пользователями и автоматическая выдача VPN-доступа остаются отдельными задачами. При подключении Android пробует Hysteria2, затем VLESS на каждом узле из подписанного пакета. Автоматическое переключение при обрыве уже работающего туннеля и другие серверы ещё не реализованы. Подробности — в `docs/publication.md`.
