# Виртуальный Помощник Нона

Ранний каркас кроссплатформенного VPN-клиента. Сейчас репозиторий содержит Flutter-приложение для Android, iOS, Windows и macOS, вход в аккаунт через HTTPS, регистрацию устройства с локальным ключом, проверку и защищённое локальное хранение подписанных обновлений, а также проектные документы. **VPN-соединение и выдача конфигураций пока не реализованы.** Никакие действующие ключи, ссылки подписки или сертификаты не включены.

## Состав

- `apps/client` — общий интерфейс Flutter, вход в аккаунт, регистрация устройства, проверка подписанных конфигураций, защищённое хранение, выбор узла и экран выбора прямых приложений Android.
- `services/control-api` — сервер аккаунтов, сессий и устройств с PostgreSQL. По умолчанию слушает только `127.0.0.1:8080`; выдача конфигураций отключена.
- `docs/architecture.md` — компоненты, безопасность и границы возможностей ОС.
- `docs/mvp.md` — этапы реализации и критерии приёмки.
- `docs/api.md` — планируемый контракт аккаунтов и выдачи конфигураций.
- `docs/backend.md` — запуск аккаунтов на домашнем сервере.
- `docs/privacy-and-threats.md` — видимость VPN и границы защиты от других приложений.
- `docs/app-routing.md` — что видно приложению при прямом и VPN-маршруте.
- `test-vectors` — общий вымышленный пакет для проверки совместимости Go и Flutter.

## Локальный запуск

```sh
cd apps/client
flutter run
```

Для подключения к собственному серверу аккаунтов задайте HTTPS-адрес при сборке: `flutter run --dart-define=NONA_API_BASE_URL=https://example.invalid`. Без адреса экран показывает, что сервер не настроен. Пароли, токены и IP VPN-узла в параметр сборки не добавляйте.

```sh
cd services/control-api
go test ./...
go run ./cmd/api
```

Публиковать API в интернет пока нельзя: защищённая выдача конфигураций и отзыв VPN credentials ещё не написаны. Для домашнего сервера потребуется HTTPS reverse proxy, постоянный адрес или домен и продуманное поведение при недоступности дома. Порядок настройки аккаунтов — в `docs/backend.md`.
