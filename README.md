# Виртуальный Помощник Нона

Кроссплатформенный VPN-клиент. Flutter-приложение входит через отдельный Keycloak Ноны, регистрирует устройство и проверяет подписанные обновления. Сервер выдаёт каждому устройству зашифрованные доступы VDSina и Aeza, в этом порядке. Клиент пробует Hysteria2, затем VLESS+REALITY на каждом узле. TUN работает на Android, Windows и macOS. iOS-сборка с Packet Tunnel и Xray компилируется, но ещё требует подписи и проверки трафика на iPhone. Секреты, ссылки подписки и сертификаты в репозиторий не включены.

## Состав

- `apps/client` — общий интерфейс Flutter, вход в аккаунт, регистрация устройства, проверка подписанных конфигураций, защищённое хранение, раздел «Интернет без VPN» для Android и TUN-подключение через Xray на Android, macOS и Windows.
- `services/control-api` — API аккаунтов, устройств и пакетов конфигурации с PostgreSQL и проверкой токенов отдельного Keycloak. Закрытая служба администратора применяет решения о доступе и автоматически создаёт либо отзывает данные доступа на VDSina и Aeza.
- `docs/architecture.md` — компоненты, безопасность и границы возможностей ОС.
- `docs/engine-choice.md` — проверка ядер Happ/v2rayN/v2rayNG и выбор Xray плюс Hysteria 2 для Ноны.
- `docs/desktop.md` — пробные TUN-сборки для macOS и Windows, установка и ограничения.
- `docs/ios.md` — текущий этап iOS, Packet Tunnel и варианты распространения вне App Store.
- `docs/mvp.md` — этапы реализации и критерии приёмки.
- `docs/api.md` — действующие маршруты аккаунтов и выдачи заранее установленных конфигураций.
- `docs/backend.md` — запуск аккаунтов на домашнем сервере.
- `deploy/home` — Docker-размещение для существующего Caddy на домашнем сервере, отдельный домен и проверки перед публикацией.
- `docs/publication.md` — фактическое состояние публичного HTTPS, отдельного Keycloak и панели.
- `docs/github-release.md` — выпуск подписанного Android APK.
- `docs/desktop-release-notes.md` — установка пробных выпусков Windows и macOS и их ограничения.
- `docs/credential-encryption.md` — формат шифрования данных доступа для устройства.
- `docs/privacy-and-threats.md` — видимость VPN и границы защиты от других приложений.
- `docs/app-routing.md` — что видно приложению при прямом и VPN-маршруте.
- `test-vectors` — вымышленные пакеты подписи и шифрования для проверки совместимости Go и Flutter.
- `third_party` — происхождение Android-библиотеки Xray и тексты лицензий.

## Локальный запуск

```sh
cd apps/client
flutter run
```

Для тестовой Android-сборки запускайте `apps/client/build-android-debug.sh`: он задаёт HTTPS-адрес и закреплённый публичный ключ проверки подписанных конфигураций из `apps/client/trust/nona-config-2026-11.b64`. Публичный HTTPS и вход через Keycloak на тестовом Android уже проверены. Сборка без этого ключа не принимает обновления. Пароли, токены, закрытый ключ подписи и IP VPN-узла в параметры сборки не добавляйте.

Android APK публикуется через GitHub Actions по тегу `v*`. Настольные ранние выпуски Windows и macOS публикуются по тегу `desktop-v*`; macOS-архив пока ad-hoc подписан и не нотариализован. Порядок установки и ограничения описаны в `docs/github-release.md`, `docs/desktop-release-notes.md` и `docs/desktop.md`.

Один аккаунт может использовать несколько устройств. После входа каждое устройство автоматически регистрирует свой ключ и получает отдельные VPN credentials; пользователь не копирует ссылки. Это позволяет отключить потерянное устройство без замены ключей на остальных. Общий ключ на весь аккаунт был бы проще на сервере, но не позволил бы выборочно отзывать доступ.

```sh
cd services/control-api
go test ./...
go run ./cmd/api
```

Отдельные Keycloak и API опубликованы через домашний Caddy. Панель доступна пользователям с ролью администратора: она показывает состояние служб, список пользователей и позволяет разрешать или отзывать VPN-доступ. Только исходный администратор `roman` может назначать других администраторов и удалять аккаунты. На Android раздел «Интернет без VPN» содержит правила для российских сайтов и приложений, свои сайты и выбор отдельных приложений; на Windows и macOS есть маршрутизация сайтов, а на Windows также приложений. При подключении клиент перебирает узлы в порядке VDSina → Aeza, сначала Hysteria2, затем VLESS. На Android и Windows активная проверка может переключить узел после двух ошибок подряд, пока Нона запущена. Подробности — в `docs/publication.md`, `docs/desktop.md` и `docs/ios.md`.
