# Нона на домашнем сервере

Проверено 9 ноября 2026 года по SSH: домашний сервер `192.168.3.24` работает на Linux x86_64; Caddy 2.11.4 и PostgreSQL 18.6 запущены в Docker. Caddy подключён к сети Docker `proxy`, его конфигурация находится в `/srv/docker/caddy/Caddyfile`. Пользователь `server-admin` может запускать Docker и редактировать Caddyfile без sudo. Это размещение рассчитано именно на эту схему.

По состоянию на 9 ноября внутренняя часть установлена: контейнеры `nona-api-1` и `nona-db-1` работают без опубликованных портов, в MikroTik сохранена статическая запись `nona.server.basketref.ru → 192.168.3.24`, а Caddy обслуживает локальное имя с внутренним сертификатом. Запрос `/v1/info` возвращает 200, `/` и `/readyz` через Caddy возвращают 404. Homarr после изменения продолжает отвечать 200.

## Схема

`https://nona.server.basketref.ru/v1/*` → существующий Caddy → контейнер `nona-api:8080` → отдельная база PostgreSQL в сети `nona_private`. API и БД не публикуют порты хоста. API находится в общей с Caddy сети `proxy`, поэтому другие контейнеры в этой сети технически могут обратиться к нему; авторизация API обязательна. VPN-трафик клиента идёт напрямую к узлам, а не через домашний сервер.

Корень сайта и `/readyz` возвращают 404 через Caddy. Панель оператора появится позже, когда будут готовы отдельная аутентификация, роли и защита от CSRF. Парсеры, боты, provisioner для VDSina и затем AdminVPS/Aeza станут отдельными процессами без публичных портов; источники и действия ботов ещё нужно определить. Сейчас API не создаёт и не отзывает VPN credentials на узле.

## Сборка и установка внутренней части

Из корня репозитория выполните `deploy/home/build-bundle.sh /путь/к/папке`. Скрипт собирает статический Linux x86_64 бинарный файл и копирует в папку `compose.yaml`, `Dockerfile`, SQL-миграции и пример блока Caddy. Передайте папку в `/srv/docker/nona` на сервере, не добавляя туда ключи из чата или клиентские подписки.

На сервере создайте каталог `/srv/docker/nona/secrets` с правами `0700`. Создайте в нём случайный файл `db_password`, например через `openssl rand -base64 48`. Для этой установки файл имеет права `0444`: Docker Compose сохраняет права файла при монтировании, а внутри контейнеров его должны читать разные непривилегированные пользователи. Каталог `0700` закрывает файл от других пользователей хоста; доступ к Docker на этом сервере сам по себе даёт доступ к секрету. Compose подключает файл к API и PostgreSQL, пароль не хранится в переменных окружения. Не отправляйте его в чат и не добавляйте в Git. Для БД используется отдельный Docker volume `nona_db_data`; миграции в `sql/` применяются PostgreSQL при первом создании пустого тома. На действующем томе они автоматически повторно не применяются: для обновлений понадобится отдельный мигратор и резервная копия.

Проверьте `docker compose config --quiet`, затем запустите `docker compose up -d --build` в `/srv/docker/nona`. Команда запускает только контейнеры проекта `nona`; существующие контейнеры других проектов не пересоздаются. Убедитесь, что `docker compose ps` показывает работающие API и БД. Проверить готовность можно запросом из Caddy к `http://nona-api:8080/readyz`. Ответ 200 означает доступность БД. Внешний маршрут `/readyz` закрыт. Учётную запись позже можно создать командой `docker compose exec -it api /admin create-user ИМЯ`; пароль вводится локально в терминале и не передаётся в командной строке.

## Домен и сертификат

Текущие `homarr.server.basketref.ru` и `cockpit.server.basketref.ru` используют A-запись `192.168.3.24`, статическую запись DNS в MikroTik и `tls internal` в Caddy. Для Ноны выбран тот же локальный шаблон: A-запись `nona.server.basketref.ru` уже добавлена у Beget, в MikroTik нужна статическая запись `nona.server.basketref.ru → 192.168.3.24`. У действующих статических записей MikroTik TTL 86400 секунд; новая запись пока приходит из внешнего DNS с TTL 600 секунд. Caddyfile для Ноны тоже использует `tls internal`.

После DNS добавьте содержимое `Caddyfile.nona.example` в `/srv/docker/caddy/Caddyfile` один раз. Проверьте `docker exec caddy caddy validate --config /etc/caddy/Caddyfile`, затем перезагрузите Caddy штатным способом. Проверьте локально `https://nona.server.basketref.ru/v1/info`. Доступ к адресу `192.168.3.24` вне домашней сети возможен только через отдельно настроенный удалённый доступ. Для самостоятельной работы VPN-клиента вне дома потребуется отдельный публично доступный HTTPS-адрес API с обычным доверенным сертификатом либо другой надёжный канал к домашнему серверу; текущий внутренний адрес нельзя указывать как `NONA_API_BASE_URL` в сборке для пользователей вне дома. Нельзя отключать проверку сертификата в приложении.

## Перед приглашением пользователей

Нужны резервное копирование и восстановление базы, мониторинг, автоматическая выдача и отзыв индивидуальных VLESS+REALITY/Hysteria2 credentials на VDSina, защита публичной точки входа от перебора и независимая проверка криптографического протокола. Сейчас рабочая панель, парсеры и боты ещё не реализованы. При недоступности дома клиент должен продолжать использовать последнюю сохранённую действительную конфигурацию, но вход и обновление будут недоступны.
