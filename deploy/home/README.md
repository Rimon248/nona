# Нона на домашнем сервере

Состояние на 12 ноября 2026 года: отдельные контейнеры API, двух баз PostgreSQL, Keycloak Ноны и OAuth2 Proxy панели работают без опубликованных портов хоста. Caddy публикует `https://nona.server.basketref.ru` с сертификатом Let's Encrypt. Публичная DNS-запись указывает на `78.107.88.57`, локальная MikroTik — на `192.168.3.24`. Существующий Keycloak BasketStat не используется и не изменён. Закрытый provisioner подключён к VDSina и Aeza; VDSina остаётся основным узлом, Aeza резервным.

Маршруты: `/auth/realms/nona*` и `/auth/resources/*` → Keycloak; `/v1/*` → API; `/admin/*` и `/oauth2/*` → OAuth2 Proxy. Корень переводит на панель. Административные пути самого Keycloak, `master` realm, `/healthz` и `/readyz` не опубликованы. Персональные API требуют OIDC Bearer token; `/v1/info` открыт для проверки версии и состояния. API запущен с `compose.oidc.yaml`, миграция `004_oidc_accounts.sql` применена после резервной копии.

## Сборка пакета

Из корня репозитория выполните `deploy/home/build-bundle.sh /путь/к/папке`. Пакет содержит бинарники Linux x86_64, миграции, файлы Compose, панель, шаблон области Keycloak и примеры Caddy. Секреты в него не входят. На сервере они находятся в `/srv/docker/nona/secrets` с закрытым доступом. Не добавляйте пароли и VPN-конфигурации в Git, архивы или чат.

Слои Compose: `compose.yaml` запускает API и его БД, `compose.identity.yaml` — отдельный Keycloak и его БД, `compose.oidc.yaml` включает проверку Keycloak-токенов в API, `compose.auth.yaml` запускает защиту панели. Они используют один проект Docker. Не запускайте `--remove-orphans` при обновлении отдельного слоя. `compose.auth.yaml` доверяет служебным заголовкам только текущему IP Caddy `172.21.0.5/32` в сети `proxy`; после пересоздания Caddy проверьте его IP и обновите параметр.

## Вход и ограничения

Почта не подтверждается. Самостоятельная регистрация включена; новый аккаунт не получает VPN-конфигурацию до разрешения администратора. Панель требует роль `nona-operator`. У `roman` исходный пароль хранится только на домашнем сервере; его следует сменить при первом входе. Восстановление через почту выключено.

Панель показывает доступность входа и API, список пользователей и решения о VPN-доступе. Только исходный администратор `roman` назначает и снимает роль администратора и удаляет аккаунты пользователей. Удаление подтверждается вводом имени пользователя, отзывает данные доступа на всех узлах, затем удаляет пользователя Keycloak и данные Ноны; аккаунт `roman` защищён. Служба `admin-api` обрабатывает разрешённые устройства и отзывы доступа каждые 15 секунд. Неудачная или частичная выдача откладывается на 1–15 минут; панель показывает число устройств, которым выдача повторяется. Миграция `008_account_deletion.sql` обязательна перед обновлением API. Ручные команды `admin provision-device ACCOUNT_ID DEVICE_ID` и `admin retire-device ACCOUNT_ID DEVICE_ID` остаются для обслуживания.

## Операторская выдача конфигурации

Команда `provision-device` требует доступ к БД Ноны, приватные файлы параметров узлов и токены 3x-ui, PEM сертификаты панелей, приватный Ed25519 ключ (`NONA_CONFIG_SIGNING_KEY_FILE`) и идентификатор ключа (`NONA_CONFIG_KEY_ID`). Файлы с токенами и параметрами должны иметь права `0600` и храниться вне репозитория. Переменная `NONA_NODES_FILE` указывает на закрытый JSON-манифест; образец и Compose overlay находятся в этом каталоге. Порядок узлов задаёт приоритет: VDSina, Aeza. Параметры каждого сервера лежат в закрытом JSON с полями `panel_url`, `host`, `vless_reality` и `hysteria2`. Серверный закрытый ключ REALITY не переносится с VPN-узла; `panel_url` включает закрытый путь панели и не публикуется.

Команда создаёт отдельные учётные данные устройства на доступных узлах, читает только эти записи и формирует подписанный пакет. Если один узел временно недоступен, работающая конфигурация остальных всё равно устанавливается, а повторная выдача добавит пропущенный узел после восстановления панели. В ночь на 12 ноября provisioner обновил 8 устройств и создал по одной записи на VDSina и Aeza. Клиент пробует узлы в порядке манифеста, для каждого сначала Hysteria2, затем VLESS+REALITY. В БД Ноны хранится только шифротекст для публичного ключа устройства. `retire-device` удаляет записи с каждого узла, указанные для устройства в БД, и только после этого отзывает устройство. Переключение клиента и реальный трафик через Aeza ещё проверяются.

Проверки публичного доступа и текущий статус — в [документе публикации](../../docs/publication.md).
