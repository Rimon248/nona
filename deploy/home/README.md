# Нона на домашнем сервере

Состояние на 10 ноября 2026 года: на домашнем сервере работают отдельные контейнеры `nona-api`, `nona-db`, `nona-identity` (Keycloak) и `nona-identity-db`. Они не публикуют порты хоста. Существующий Keycloak BasketStat не используется и не изменён. Caddy обслуживает локальный `nona.server.basketref.ru` с `tls internal`: маршруты `/auth/realms/nona*` и `/auth/resources/*` ведут к Keycloak Ноны, `/v1/*` — к API. `/auth/admin/`, `/auth/realms/master` и `/readyz` снаружи закрыты. Homarr продолжает отвечать.

API запущен в OIDC-режиме. Миграция `sql/004_oidc_accounts.sql` применена после резервной копии БД. `GET /v1/info` возвращает `authentication=keycloak`, `provisioning_enabled=false`. Маршруты старого входа `/v1/sessions*` выключены. Отдельный Keycloak имеет область `nona`, публичный клиент `nona-client`, закрытый клиент панели `nona-panel` и роль `nona-operator`.

## Сборка пакета

Из корня репозитория:

```sh
deploy/home/build-bundle.sh /путь/к/папке
```

Пакет содержит бинарники Linux x86_64, миграции, `compose.yaml`, дополнительные `compose.identity.yaml`, `compose.oidc.yaml`, `compose.auth.yaml`, скрипт запуска Keycloak и примеры Caddy. Секреты в пакет не входят. Для нового сервера нужны отдельные случайные пароли базы API, базы Keycloak и bootstrap-администратора, а также секрет клиента панели и cookie в `/srv/docker/nona/secrets`. Каталог должен иметь права `0700`; значения не вводите в чат, не добавляйте в Git и не передавайте в параметрах команды. На действующем сервере файлы уже созданы.

`compose.yaml` запускает API и его БД, `compose.identity.yaml` — отдельный Keycloak и его БД, `compose.oidc.yaml` переключает API на проверку токенов Keycloak. Команда `docker compose up` без дополнительных файлов не воспроизводит действующий режим. На живом сервере не запускайте `--remove-orphans`: разные слои Compose используют один проект.

## Публикация и оператор

Публичная A-запись у Beget всё ещё ведёт на частный `192.168.3.24`, как и локальная запись MikroTik. Для внешнего доступа публичную запись нужно направить на внешний IP домашнего подключения, локальную сохранить. Затем Caddy должен получить обычный доверенный сертификат. Порядок и проверки описаны в [плане публикации](../../docs/publication.md).

Первый оператор `roman` создан с временным паролем в `/srv/docker/nona/secrets/roman_initial_password`. Почта не подтверждена; требуется настроить SMTP и пройти одноразовую ссылку Keycloak. `compose.auth.yaml` пока не запущен и маршрут панели не открыт. Текущий upstream панели `static://200` служит только проверкой входа; рабочие действия панели ещё не реализованы.

Парсеры, боты и provisioner для VDSina, затем AdminVPS и Aeza, будут отдельными внутренними процессами. Пока API не создаёт и не отзывает VPN credentials на узлах, а приложение не подключает полученный пакет к VPN-ядру. Для использования сервиса нужны резервное копирование обеих баз и проверка восстановления.
